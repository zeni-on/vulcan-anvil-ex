# Product Document Growth Regression

상태: PR #31의 구현·합성 회귀, PR #36 이후 main과 통합
최초 검증: 2026-09-10 / 통합 정리: 2026-09-11

## 1. 목적과 범위

[작성 지침](../core/PRODUCT_DOCUMENT_WRITING.md)의 구조가 최초 작성뿐 아니라 기능 확장에도 유효한지 확인했다. 실제 사용자 프로젝트 대신 가상 요청 보드 문서로 시나리오 3개→댓글 추가→제목 제한 변경을 재현했다. 로컬 예시의 가상 업무 문서는 프레임워크에 배포하지 않으며 자동 회귀는 임시 디렉터리의 합성 입력을 사용한다.

이 검증은 앱 개발·제품 QA·성능 측정·릴리즈 승인이 아니다. 실제 예시 session은 Phase 0 / pending이며, Gate 3/4 판정은 단계 인자를 주는 검사와 별도 임시 회귀 프로젝트에서 확인했다. 기존 PMTool 원본은 수정하지 않았다.

## 2. 확인된 작성 방식

| 반복 | 변경 | 문서 처리 |
| --- | --- | --- |
| v0.1 | 요청 등록·결정·조회 | 6종 진입점 + 요구/API/데이터/UI/보안/개발/시험/미실행 상세 |
| v0.2 | 독립 댓글 기능 | 필요한 분야의 상세 5개와 새 미실행 현황 1개 추가; 원장은 색인·관계·현재 결과 링크 보강 |
| v0.3 | 제목 100자→200자 | 기존 요구/API/데이터/시험 원본 4개 현행화; 현재 결과 링크와 새 미실행 현황만 추가 |

- 원장 수는 6개로 유지하되 상세 파일 수를 제한하지 않는다. 작성 산출물은 14→20→21개였다. 마지막 단계의 증가는 결과 현황 1개이며 계약 파일을 버전별로 복제하지 않았다.
- v0.2에서 기존 요구/API/데이터/개발 기준/시험/옛 결과/ADR 7개 원본을 보존했다. 필요한 공통 보안 적용 범위와 부모 화면 연결은 수정했다.
- v0.3에서 변경한 기존 Markdown은 5개(계약/시험 4개와 보고서 1개), 다른 기존 산출물 15개는 동일했다. 페이지 최대 100건과 댓글 500자 제한은 유지했다.
- 원장 전체 줄 수는 308→325→327이었다. 줄 수를 강제 기준으로 삼지 않는다. 이 관찰만으로 비용·속도 개선이나 대규모 탐색 성능을 보장하지 않는다.
- 같은 의미의 ID를 유지하고 해당 원본의 현재 조건을 갱신한다. 최신 규격을 날짜순 추가 설명에서 추론하게 하지 않는다.
- 과거 결과 파일의 상대 링크는 최신 시험 정의를 열 수 있다. 실제 실행 묶음에는 당시 소스와 시험 정의의 Git/스냅샷 기준을 연결해야 한다. 결과 파일의 byte 보존만으로 과거 시험 입력까지 보존했다고 판단하지 않는다.

## 3. Gate 3 미실행 오탐 수정

Product Gate 3 시험 계획 시점에 결과 표를 미리 만들면 `Not Run` 행이 실제 실패처럼 처리됐다. `product_verification_result_findings`에서 **Gate 3의 명시적 미실행만** 안내로 분리했다.

| 상태 / 단계 | 처리 |
| --- | --- |
| Gate 3: Not Run / not_run / not-run / not_executed / 미실행 | 계획 완료를 단독 차단하지 않음; 미실행 ID를 하나의 안내로 집계 |
| Gate 3: Fail / Blocked / environment_blocked | 기존 차단 유지 |
| 상충된 현재 결과 또는 Result·Status 충돌 | 차단 유지 |
| Gate 4 / Gate 5 / completed의 필수 미실행 | 실행 완료로 인정하지 않음 |
| Impl self-check / 다른 profile | 이번 Gate 3 예외 대상이 아님 |

상태 문자열의 하이픈 표기도 기존 정규식 허용 범위와 일치하도록 정규화한다. 안내는 Pass 승격이나 Gate 자동 승인으로 해석하지 않는다. 인라인 결과와 링크된 결과 모두 같은 판정을 적용하며 작성 문서를 수정하지 않는다.

## 4. 검증

자동 회귀:

- [Product 단계별 판정](../../scripts/regression/tests/test_product_workflow.py): 미실행 표기 변형, 실제 실패/환경 차단, 상충된 결과, 인라인/분리 문서 전환 진단, 원본 미변경, 후속 단계 차단.
- [기능 확장 회귀](../../scripts/regression/tests/test_product_growth.py): 3→4 시나리오, 현재 계약 변경과 기존 ID/비관련 원본 보존, Git의 과거 시험 정의 조회, 현재 조건 부분 조회, 누락 링크/상충 정의 차단, 과거 합성 Pass의 현재 범위 재사용 방지.

## 5. 다음 경계

- 상태·승인·소스 비교와 Dashboard 읽기/릴리즈 미리보기의 현재 지원 범위는 [3구간 프로세스 계약](PRODUCT-PROCESS-CONTRACTS.md#44-운영-소비자-연결-단계-2c)을 따른다. 남은 실제 운영 라우팅과 반복/이행 보존 검증은 별도이며, 이 문서 확장 회귀 자체가 새 프로세스의 전체 실행 성공을 뜻하지 않는다. 이번 작업에 자동 문서 이동은 없다.
- 기능 수가 더 많아지면 색인도 커진다. 실제 원본 구조와 조회 결과를 보고 분리 책임을 조정하며 고정 줄 수/파일 수 정책을 추가하지 않는다.
- 실제 기능의 승인된 이동과 실제 QA 실행은 문서 구조 회귀와 구분한다. 과거 실행의 미완료 의무를 History로 이동했다는 이유만으로 닫지 않는다.

현재 우선순위는 [로드맵](../ROADMAP.md)을 따른다.

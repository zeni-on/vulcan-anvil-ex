> 상태: 로컬 문서 구조 파일럿 완료. 제품 QA/마이그레이션/성능 입증이 아니다.
> 관측일: 2026-09-10 (KST)
> 설계: [문서 지도와 이행 계획](PRODUCT-DOCUMENT-ARCHITECTURE-STRATEGY.md)

## 1. 범위

진행 중인 Product 프로젝트의 Gate 1 후보 기능 하나를 저장소 밖 임시 작업공간에 복사했다. 요구/AC 7쌍, 관련 범위 전환 결정, 추적 연결, 이전 검증의 Pending 9건을 대상으로 삼았다. 실제 프로젝트는 `product`, `gate1` 상태였으며 새 설계/시험/구현을 승인한 것으로 해석하지 않았다.

4개 입력 문서를 파일별 읽기 전/복사본/읽기 후 SHA-256으로 확인했다. 세션은 hash/현재 Gate를 관측했고, 원본에 CLI 쓰기/문서 이동/제품 명령을 수행하지 않았다. 전체 저장소의 동시 작업 부재나 원자적 스냅샷을 증명하는 검사는 아니다.

로컬 산출물:

- `baseline/`: 관측한 원문 4개.
- `proposed/README.md`: 파일럿 탐색 시작점.
- `proposed/docs/artifacts/01-requirements/`: 목록, 기능별 요구/AC, 공통 범위/권한/미확정 조건.
- `proposed/docs/product/PRODUCT_TRACEABILITY.md`: 범위가 한정된 연결 후보.
- `proposed/docs/artifacts/04-review/`: 이전 미완료 결과의 보존 묶음.
- `proposed/docs/artifacts/05-change/`: 관련 결정/이관 책임.
- `proposed/sources/`: 출처 보관 전용. 편집할 두 번째 원장이 아님.
- `manifest.json`, `verification.json`, `lookup-before.json`, `lookup-after.json`: 해시/구조 검사/기존 CLI 조회 관측.

정확한 로컬 위치는 사용자에게 별도로 전달한다. 이 공개 문서에는 원문, 고객/운영 정보, 절대경로, Git/세션 식별자를 싣지 않는다. 공개 회귀 fixture로 실제 프로젝트를 복사하지 않는다.

## 2. 수행과 결과

| 확인 | 실제 결과 |
| --- | --- |
| 원문 4개 보존 | 복사본 및 검사 시 원본 hash 일치 |
| session 변경 | 관측 전후 hash 동일; Gate 전환 없음 |
| 요구/인수조건 | 7쌍의 원문 표현 보존, 요구 정의 heading은 각각 한 곳 |
| 공통 조건 | scope의 본문 16개 비어 있지 않은 줄 보존 확인; 링크 대상은 재연결 |
| 미완료 의무 | 9개 결과 행 전체 보존, 모두 Pending 유지 |
| 탐색 링크 | 분리 문서/목록의 로컬 링크 23곳 파일 존재, 명시 anchor 대조 |
| 포착하지 않은 참조 | 3개 경로를 미수집으로 표시; 파일을 채운 척하지 않음 |
| 기계적 검사 | 103개 assertion 통과. 독립적인 제품 테스트 103건이라는 뜻은 아님 |
| 새 승인/실행 결과 | 후보 상태 유지. 새 API/DB/UI/시험 ID 또는 Pass 생성 없음 |

원문을 기계적으로 분리하고 요구/AC 표현을 유지하는 방식이었다. CR과 범위 문서에 남은 설명 중복까지 의미적으로 재작성한 최종 템플릿은 아니다. 변경할 원본 위치와 탐색 경로를 확인했지만 실제 요구 변경/개발을 실행해 생산성을 비교한 것은 아니다.

## 3. 조회 비교와 중요한 한계

같은 요구 ID에 기존 `trace-context --sections --emit json --max-chars 12000`을 실행했다. 원본/분리본 각각의 문서 경로를 `--document`로 명시했다. 이 조회는 읽기 안내이며 Gate 검사나 승인 도구가 아니다.

| 관측 | 원본 | 분리본 |
| --- | --- | --- |
| 비교용 콘텐츠 전체 UTF-8 bytes | 336,454 (4개 파일) | 28,793 (6개 콘텐츠 파일; 탐색 README/출처 복사 제외) |
| 해당 ID 조회 excerpt 문자 수 | 10,463 | 3,013 |
| 선택 절 / 제한으로 빠진 절 | 9 / 0 | 9 / 0 |
| `incomplete` | true | true |
| 경고 수 | 1 | 1 |

**이 숫자를 동일 정보량 대비 읽기 비용 절감으로 해석하면 안 된다.** 전체 파일 비교는 한 기능만 추출한 효과를 포함하고, 분리본의 ID 조회에는 공통 범위 문서와 Pending 결과 문서의 본문이 선택되지 않았다. 파일럿 당시 조회기는 명시적으로 문서를 입력해도 ID/제목 규칙에 매칭되지 않는 내용을 반환하지 않았으며 링크를 자동으로 따라가지 않았다. 후속 조회 보강 결과는 6절에 별도로 남긴다.

따라서 반환량이 줄어든 부분에는 필요한 조건이 빠진 영향이 있다. 분리본을 실제 handoff로 사용하려면 공통 조건/관련 결정/미완료 의무를 별도로 읽어야 한다. 누락된 참조까지 포함한 의미 보존과 토큰/크레딧·작업 시간의 절감은 입증하지 않았다.

## 4. 결정과 다음 구현

문서별 책임을 분리하고 같은 요구의 정의 위치를 찾는 구조는 확인했다. 그러나 조회만 보강한 채 내용/Gate 검사와 작성 경로를 확인하지 않고 원장을 색인으로 바꾸는 migration은 보류한다.

1. 다음 구현은 새 템플릿 대량 생성보다 **관련 문서 원본과 적용 공통 조건을 제한적으로 찾는 조회/검사 호환**이다.
2. 기존 기본 탐색이 새 요구사항/시험 폴더를 놓치는 경우와 링크 조건이 선택되지 않는 경우를 합성 회귀로 고정한다.
3. legacy/split/mixed 배치의 의미가 일치하고, 누락/순환/범위 밖/충돌이 보고되면 작성 경로까지 새 위치에 맞춘다.
4. 그 후 실제 기능 하나의 문서 이동을 별도 승인받아 진행한다. 원문 이동과 계약 내용 변경은 분리하고 Audit/PoC 회귀를 유지한다.

새 DB, 문서마다 SHA 필드, 새 필수 Run, 전체 프로젝트 재작성은 이 파일럿의 결론이 아니다.

## 5. 독립 설계 리뷰

부모 대화를 상속하지 않은 native reviewer에게 설계/작성 계약 두 문서만 읽기 전용으로 전달했다. 모델 override는 생략하고 effort는 medium으로 지정했다. 실제 모델 식별자를 별도로 확인한 것은 아니다. reviewer는 사용자 프로젝트를 읽거나 파일을 수정하지 않았다.

반영한 지적:

- P1: 미완료 의무는 보존 선언뿐 아니라 기존 FIND/ISSUE/CR 중 관리 원본, 담당, 적용 조건과 종료 근거를 정해야 한다.
- P2: 당시에는 과거 시험 결과에서 테스트 정의의 Git 기준/보존 스냅샷을 찾도록 요구했다. 이 Git 증적 요구는 이후 폐기되었으며 현재는 테스트 정의 revision과 실제 결과·로그를 연결한다. 과거 리뷰 결과를 재작성한 것은 아니다.
- P2: 조회뿐 아니라 템플릿/adapter/이미 열린 담당 작업의 작성 원본도 전환돼야 한다. 구형 작성 경로가 남으면 이동을 보류한다.

총괄은 지적을 설계와 작성 계약에 반영하고 파일럿 원문/해시/조건/연결을 기계적으로 대조했다. reviewer의 의견은 새 실행 정책 승인이나 마이그레이션 검증을 대신하지 않는다.

설계 문서 추가 후 기존 절 조회 회귀 `test_document_context.py` 33건 중 32건이 통과했고 symlink 생성 권한에 따른 1건은 skip이었다. 이는 기존 조회 기준선 확인이며 새 분할 형식의 end-to-end 지원 검증이 아니다.

## 6. 조회 호환 MVP 재확인 (2026-09-10)

요구/시험 폴더 탐색과 제한된 명시적 참조 조회를 구현한 뒤, 같은 로컬 분리 복사본을 읽기 전용으로 다시 조회했다. 운영 중인 프로젝트 원본이나 승인 상태는 변경하지 않았다.

- 분리본 `docs/`의 README를 제외한 5개 문서를 명시해 요구 ID를 조회했다. 12절/4,608자가 반환됐고, 이전에 빠졌던 공통 범위 문서의 7절이 포함됐다.
- 25절이 출력 제한으로 빠졌으며 `incomplete: true`였다. Pending 문서도 한 번의 출력에 들어오지 않았고, 참조의 `output_limit` 등 미수집 사유가 표시됐다. 이는 완전한 handoff가 아니다.
- Pending 원본 문서와 해당 시험 ID로 조회를 좁히면 2절/2,085자가 반환됐고 출력 누락은 없었다. 미수집 참조 경고 1건과 `incomplete: true`는 유지됐다. 과거 Pending을 현재 Pass로 변경하지 않았다.
- 합성 회귀에서는 단일/분리/혼합 문서의 같은 요구/공통 조건/시험 설명 보존, 출처 줄/해시, 쓰기 없음과 제한/순환/누락/미분류를 확인한다. 독립 코드 리뷰의 추가 보안 절 누락, 링크 예산, 괄호 파일명, 중복 링크 정의 지적도 회귀에 반영했다.

최종 로컬 Python 회귀는 158건 중 155건 통과/3건 skip, 기존 Audit/Product/PoC fixture smoke는 84단계 통과였다. 이 중 절/연결 조회 전용 테스트는 61건이다. 실제 프로젝트의 Gate/제품 QA를 재수행했다는 의미는 아니다.

입력 문서 선택과 조회 동작이 달라졌으므로 3절과 동일 정보량의 속도/비용 비교로 사용하지 않는다. 실제 문서 이동 전 내용/Gate 검사, 추적/통계, 작성 템플릿/adapter, Dashboard의 호환성 검증은 여전히 남아 있다.

# Vulcan-Anvil Ex v0.4.9

Released: 2026-06-26

`v0.4.9` is a profile and runtime stabilization patch. It keeps the `v0.4.8` Product profile direction, then locks more of the real operating behavior into fixture smoke tests and Dashboard checks.

## Highlights

- Added `doctor` and `doctor --json` as a structured local environment diagnostic.
- Added `execute --dry-run` and `execute --dry-run --json` as an Orchestrator-facing pre-execution facade.
- Added Dashboard/runtime support for native delegation sidecars and worker verification state.
- Added Codex model fallback reporting for unsupported model aliases.
- Tightened Product Gate 4 and Gate 5 readiness checks using real Product sample reruns.
- Tightened PoC evidence handling so `Pass` / `Smoke Pass` does not count as implemented unless a real evidence file exists.
- Stabilized Dashboard Jest discovery so generated Next/Playwright artifacts do not break tests.

## Product Profile

Product projects now have stronger release readiness checks without being forced into Audit artifacts.

- Product Gate 4 blocks rows that still say `Not run yet | Planned`.
- Product Gate 5 requires `docs/artifacts/07-release/DOC-PM-G5-001_Release-Approval_v0.1.md`.
- Product `release-pr --dry-run` continues to use Product evidence, backlog, and the Gate 5 approval document instead of Audit-only QA documents.
- Product implementation stats are read from the Product traceability source of truth.

## PoC Profile

PoC remains lightweight, but optimistic success reporting is now blocked.

- `POC_TEST_REPORT.md` may use `Smoke Pass`, but the referenced evidence file must exist.
- PoC implementation stats no longer count requirements as implemented from text alone.
- A repeated PoC sample rerun confirmed that `Fix Log / Experiment Iterations` can preserve what changed and why across multiple small additions.

## Runtime And Delegation

This release improves the Orchestrator's ability to see what actually ran.

- `.vulcan/delegations/*.json` sidecars can be surfaced as native subagent/thread/Agy branch delegation records.
- Worker completion and Orchestrator verification are separated more clearly.
- `execute --dry-run --json` exposes planned checks, scope, verification commands, and delegation sidecar candidates.
- `doctor --json` can be used as QA-000 environment evidence and as a structured diagnostic before runner/UI issues are treated as product defects.

## Dashboard

- Dashboard document comments, Trace Explorer, QA evidence, Product/PoC document routes, and delegation records remain part of the main operating path.
- Jest now ignores generated `.next`, `test-results`, `playwright-report`, and `node_modules` paths so tests are not affected by prior local builds.

## Upgrade Notes

Run:

```powershell
python vulcan.py upgrade
python vulcan.py version
python vulcan.py status --check
```

After upgrading:

- For Product projects at Gate 5, confirm the release approval document exists before `release-pr --dry-run`.
- For PoC projects, make sure every `Pass` / `Smoke Pass` row points to an actual evidence file.
- If local runtime, npm, Playwright, Dashboard, or runner behavior is unclear, run `python vulcan.py doctor --json` and classify failures as environment-blocked before treating them as product defects.

# Vulcan-Anvil Ex v0.4.5

Released: 2026-06-06

`v0.4.5` is a patch release for Codex-centered operation, PoC profile flexibility, and Gate 4 QA workspace defaults. It keeps the `v0.4.4` PoC compact Run direction, then makes Codex custom agents visible to generated projects and softens PoC checks where strict audit behavior slowed experiments.

## Highlights

- Added repo-local Codex custom agent definitions under `.codex/agents/`:
  - `trace-scout`
  - `run-drafter`
  - `contract-reviewer`
  - `qa-reader`
- Added user-facing Codex documentation in README, Getting Started, and the Codex/GPT adapter README.
- Changed Gate 4 QA default execution to reuse the current `workflow.integration_branch` workspace. A dedicated QA worktree is now opt-in.
- Updated PoC profile behavior so justified `TBD`, missing detailed trace links, not-run items, and `environment_blocked` can be warnings or decision items instead of automatic blockers.
- Kept real product failures, false Pass claims, and missing PoC goals/success criteria as blockers.

## Codex Custom Agents

The new `.codex/agents/*.toml` files define read-oriented helper agents for the main Orchestrator. They are intended to support investigation and review, not to approve Gates directly.

| Agent | Purpose |
| --- | --- |
| `trace-scout` | Find related IDs and likely source documents around a seed ID. |
| `run-drafter` | Review whether a Run input contract is clear enough for a worker. |
| `contract-reviewer` | Check Program/API/DB/UI contracts against implementation or design output. |
| `qa-reader` | Interpret QA logs, evidence, transcripts, stale results, and FIND/CR/ISSUE candidates. |

If the current Codex surface cannot select a native custom agent directly, the Orchestrator may fall back to a prompt-injected contract. In that case it must not claim that the TOML model/effort was automatically applied.

## PoC Profile

PoC remains a lower-process profile, not a lower-quality profile.

- Short PoC experiments can use subagents and result summaries without creating a Run for every step.
- Compact Runs are still useful for external workers, independent review, long delegation, or reproducible experiment records.
- `TBD`, `미정`, and `확정필요` are allowed only when the reason and next decision timing are recorded.
- Goals, success criteria, and actual execution results cannot be left as `TBD`.

## Gate 4 QA Workspace

Gate 4 QA now defaults to the integration branch working directory. This reduces time lost in worker/worktree dependency setup during QA, especially for Node and Playwright projects.

Projects that still need a detached QA worktree can opt in with `workflow.qa_worktree_enabled: true`.

## Upgrade Notes

Run:

```powershell
python vulcan.py upgrade
```

The upgrade path updates generated project docs and config defaults, including:

- `workflow.qa_worktree_enabled: false`
- Codex model policy cleanup for unsupported older defaults
- `.agents/skills/` and `.codex/agents/` files

# Vulcan-Anvil Ex v0.6.0

## 달라진 점

- 새 프로젝트에서는 Product 또는 Audit를 선택한다. 기능을 작게 실험할 때도 Product에서 한 시나리오만 계획하고 검증할 수 있다. 감사 산출물이 필요하면 Audit를 사용한다.
- Product에서 TC를 만들 때 **같은 시작 조건을 재현할 방법**을 함께 정한다. 단위 시험은 고정 입력으로 충분하다. 상태가 있는 시험은 시험 데이터 생성·초기화, 시작 상태 확인, 격리·정리 방법을 기존 시험 코드나 계획에 둔다. 데이터 준비 실패는 제품 실패가 아니다.
- UI가 요구한 조작, 실제 관측, 선행 실패로 못 한 후속 단계를 구분한다. 재시험은 이전 실패와 새 결과를 연결하고 이번에 실행한 고유 TC, 환경별 실행 횟수와 재사용한 결과를 섞지 않는다. 새로운 Gate나 필수 대장은 없다.
- 기능별 Product 원본과 구현 위치를 연결하고, 구조화된 QA 정의와 결과가 있는 경우 읽기 전용으로 비교할 수 있다. 보고서 생성은 QA 실행이나 인수 승인이 아니다.
- `release --target` 배포본에도 두 프로파일의 문서 템플릿, QA 지침과 CLI 모듈을 포함한다. 로컬 프로젝트 목록, 실행 결과와 내부 사례 문서는 배포 대상이 아니다.
- 대시보드 운영 의존성의 보안 경고에 대응해 Next.js 15.5.29, DOMPurify 3.4.17, sharp 0.35.5, source-map-js 1.2.2, Zod 4.6.7을 잠금 파일에 반영했다.

## 업그레이드

Product/Audit 프로젝트는 기존 작성 문서와 증적을 유지한다. 프로젝트의 작업 상태와 백업을 확인하고, 세션의 `vulcan_src`가 이번 버전의 Ex 원본을 가리키는지 확인한다. **첫 업그레이드는 대상 프로젝트 디렉터리에서 새 Ex 원본의 CLI로 실행한다.** 예를 들어 원본과 프로젝트가 이웃 폴더라면:

```console
python ../vulcan-anvil-ex/vulcan.py upgrade
python vulcan.py version
python vulcan.py status
```

이전 설치본의 복사 로직에 의존하지 않기 위한 순서다. 자세한 내용은 [v0.6.0 업그레이드 가이드](https://github.com/zeni-on/vulcan-anvil-ex/blob/v0.6.0/docs/UPGRADE_AND_DASHBOARD.md)를 따른다. 이미 작성한 TC를 일괄 수정할 필요는 없으며, 다음에 재사용할 사례부터 준비 방법을 보강한다.

**기존 PoC 프로젝트에는 이전 버전의 로컬 CLI로 upgrade를 실행하지 않는다.** PoC를 계속 열거나 과거 시험을 재현해야 하면 해당 프로젝트와 당시 Ex 버전을 함께 보존한다. v0.6.0은 기존 파일을 Product/Audit로 자동 변환하지 않는다. 개발을 이어갈 때는 별도의 Product 프로젝트를 시작하고 유효한 요구·코드·시험을 선별해 가져온다. 과거 Pass는 새 프로젝트의 실행 결과가 아니다.

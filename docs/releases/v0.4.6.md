# Vulcan-Anvil Ex v0.4.6

Released: 2026-06-07

`v0.4.6` is a patch release for native-orchestrator operation and Run handoff safety. It includes the documented `v0.4.5` Codex/PoC updates plus the newer Agy main Orchestrator and Workspace branch delegation guidance. A separate GitHub `v0.4.5` release was not published, so `v0.4.6` is the next public patch release after `v0.4.4`.

## Highlights

- Documented Antigravity/Agy as a supported main Orchestrator path, not only an external worker runner.
- Added user-facing Agy guidance in README, Getting Started, Concepts, Roadmap, and the Gemini/Antigravity adapter README.
- Aligned Agy `Workspace: branch` with Ex native delegation:
  - use `delegation_records.mode: agy-branch-agent`
  - keep Run records thin for native branch workers
  - let the Orchestrator re-verify changed files and commands in the parent workspace
- Reinforced that native subagent/thread/Agy branch delegation must run `python vulcan.py run-preflight <run-file>` before worker execution.
- Added safety checks so `run-check`, `run-preflight`, and `prepare-transition` catch more Run contract drift before Gate transition.

## Agy Main Orchestrator

Agy can act as the main Orchestrator when a generated project is opened in Antigravity/Agy. In that mode:

- `GEMINI.md` is the runtime entry document.
- Common Gate rules still come from `docs/core/`.
- Agy-specific prompt, persona, and structured output rules come from `docs/adapters/gemini/`.
- Native Agy subagents and `Workspace: branch` are treated as native delegation, not as external CLI worker execution.

The Orchestrator must still verify worker output. Native branch isolation improves speed and dependency reuse, but it does not replace Gate rules, Run scope checks, or QA/release approval boundaries.

## Run Handoff Safety

This release tightens the gap found in Agy/native worker samples:

- `run-check` and `run-preflight` compare top Run metadata with the embedded Run input contract.
- `prepare-transition` runs a preflight safety pass over completed current-Gate worker Runs.
- `prepare-transition` also checks completed/approved artifacts for obvious template placeholders and empty table rows.
- `BW-000` scaffold Runs cannot claim business requirement or test states as `Implemented`, `Verified`, or `Pass`.
- Completed worker Runs are expected to include either native `delegation_records`, external `Run Execution Record`, or an explicit direct-edit exception.

## QA Guidance

- QA Finding now has a standard `No Findings` form, so Gate 4 can close cleanly even when no FIND exists.
- Playwright dialogs should be recorded and classified. Expected dialogs may be handled; unexpected dialogs should become Fail/FIND candidates instead of being silently accepted.

## Upgrade Notes

Run:

```powershell
python vulcan.py upgrade
```

After upgrading generated projects, ask the main Orchestrator to review the runtime entry document for its environment:

- Codex: `AGENTS.md`
- Antigravity/Agy: `GEMINI.md`
- Claude: Claude adapter/project entry docs

For Agy-based projects, confirm that native worker handoffs run:

```powershell
python vulcan.py run-preflight <run-file>
```

before invoking Agy subagents or `Workspace: branch` workers.

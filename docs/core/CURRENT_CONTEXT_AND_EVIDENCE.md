# Current Context And Evidence

## 1. 목적과 범위

누적 문서의 양을 억지로 줄이기보다 현재 적용 계약과 과거 이력을 구분하고, 실제 검증 대상에 증적을 연결한다. Product 원장 6개, 기존 ID와 Gate 승인, Audit/PoC 검사 계약을 유지한다. 새 DB, 필수 Run 필드, 자동 승인 또는 자동 문서 재작성은 추가하지 않는다.

## 2. 현재 계약과 이력

- 현재 적용하는 계약은 한 위치에서 관리한다. 원장에 상세 계약을 복제하지 말고 해당 절 또는 상세 문서를 연결한다.
- 변경 이유, 과거 실행 결과, 폐기된 설계는 기존 CR/ADR/Run 또는 Git 이력으로 연결한다. 이전 버전에서 여전히 유효한 계약은 버전 적용 범위를 명시한다.
- 큰 문서를 날짜순 추가 문장만으로 운영하지 않는다. 승인된 변경을 해당 현재 계약에 반영하고, 과거 내용과의 관계를 남긴다.
- 모든 기존 문서를 즉시 이동하거나 분할하지 않는다. 관련 기능을 수정할 때 해당 영역부터 정돈하고 기존 링크/ID/검사기 호환성을 확인한다.

절의 의미를 명확히 할 필요가 있으면 제목 아래 다음 선택형 표식을 사용할 수 있다. 하위 절은 가장 가까운 표식을 상속하며 별도 표식으로 구분할 수 있다.

```markdown
## API-024 현재 적용 계약
<!-- vulcan:state=current -->

### 후속 변경 후보
<!-- vulcan:state=candidate -->

## 이전 버전 기록
<!-- vulcan:state=history -->
```

표식은 문서 작성자가 분류한 적용 상태이지 Gate 승인 증명이나 코드 구현 상태가 아니다. 표시가 없는 기존 절은 `unclassified`다. 날짜, 파일명, 최신 위치, `Delta`/`Designed`라는 표현만으로 승인된 현재 계약을 추론하지 않는다. 서로 상충하는 현재 계약도 자동으로 하나를 선택하지 않는다.

## 3. 필요한 절 조회

기존 `trace-context`에 선택적인 절 조회를 추가한다. 기존 그래프 조회/ID 매핑은 호환성을 유지한다.

- 정확한 ID와 관련 원장의 절을 찾고 제목, 줄 범위와 출처를 반환한다. 그래프에 ID가 없어도 지정 문서를 직접 조회할 수 있어야 한다.
- ID가 있는 문장만 잘라서 계약으로 취급하지 않는다. 상위 절의 공통 조건과 관련 보안/권한/오류/호환성 기준을 함께 안내한다.
- `current`, `candidate`, `history`, `unclassified`를 구분하고, 분류/누락/잘림을 숨기지 않는다. 출력량 제한은 조회 비용 제한이며 계약 완전성 보장이 아니다.
- 결과는 원문에서 파생된 읽기 안내다. 새 원장이나 승인 계약 복사본이 아니다. 원문 경로나 내용이 바뀌면 다시 조회한다. 줄 번호는 조회 당시 원문에만 유효하다. 조회용 문서 해시는 Git 증적이나 시험 소스 신선도 판정에 사용하지 않는다.
- Run에는 짧은 조회 안내와 출처를 연결한다. 전체 계약 본문, 과거 Run, 부모 대화를 매번 복제하지 않는다. 불명확하면 해당 원문과 승인 기록을 확인한다.

### 3.1 분리 문서 조회 호환 MVP

기본 조회는 `docs/product/`와 `docs/artifacts/01-requirements/`, `02-design/`, `03-test/`를 포함한다. 선택된 절의 상대 Markdown 링크를 제한적으로 따라가며, 공통 조건이 다른 파일에 있다는 이유만으로 누락하지 않도록 한다. 이는 읽기 기능이며 필수 산출물, 작성 템플릿, Gate 검사 경로를 바꾸지 않는다.

파일 링크는 해당 파일의 절들을, 제목 앵커 링크는 해당 절/하위 절/상위 조건을 후보로 삼는다. 일반 제목 기반 앵커와 중복 제목의 `-1` 접미사, 같은 문서의 `#앵커`, inline/reference-style 링크를 지원한다. HTML 사용자 정의 앵커 등 해석하지 못한 앵커는 전체 파일로 대체하지 않고 미수집으로 남긴다. 코드 예시나 외부 URL을 계약 의존성으로 자동 실행/가져오지 않는다. URL query로 지정한 과거 revision도 현재 파일로 대신하지 않는다.

링크 탐색은 최대 2단계/64개/추가 16문서이며, 전체 문서 256개, 문서당 2MB, 출력 12절/기본 12,000자 제한을 유지한다. 순환/중복은 한 번 읽은 구간을 재사용한다. 탐색 범위 밖의 CR/과거 결과가 필요하면 `--document`에 정확히 추가한다. 링크가 있다는 이유만으로 private/Run/review 디렉터리를 자동 탐색하지 않는다.

`references`는 출발 문서/줄, 대상/앵커, 읽기 상태, 출력 포함 여부를 반환한다. `source_links`에도 같은 정보가 연결된다. `missing_anchor`, `missing_or_unsafe`, `outside_lookup_scope`, `depth_limit`, `document_limit`, `output_limit` 등은 미수집 사유이며, 제한/미분류/중복 현재 구간 경고를 포함해 `incomplete`로 보고한다. 링크 파일의 상태는 출발 파일에서 상속하지 않는다. 연결된 과거 Pending/후보 계약도 임의로 현재 Pass나 승인으로 바꾸지 않는다.

ID 일치와 명시적 연결은 읽기 보조일 뿐이다. 링크가 없는 공통 조건의 완전성이나 같은 ID가 나타난 두 절의 의미상 충돌을 자동 증명하지 않는다. 원문을 옮기기 전에는 내용 검사/추적/통계/작성자 경로의 legacy/split/mixed 호환성도 별도로 검증해야 한다.

### 3.2 Product 내용 검사·추적·통계 호환

Product의 여섯 원장은 현재도 필수 진입점이다. 내용 검사와 통계는 그 파일에 있는 명시적 Markdown 링크를 통해 분리된 상세도 읽는다. 기존 원장만 있는 형식, 일부만 분리한 혼합 형식, 원장에 상세 위치를 연결한 형식에서 같은 표/ID 계약을 사용한다. 새 폴더를 전부 검색해 관련 있어 보이는 문서로 필수 내용을 대신하지 않는다.

| 진입 원장 | 해당 원장이 소유하는 상세 위치 |
| --- | --- |
| PRODUCT_BRIEF | `docs/artifacts/01-requirements/` |
| PRODUCT_ARCHITECTURE | `docs/artifacts/02-design/` |
| ADR_LOG | `docs/artifacts/02-design/architecture/` |
| PRODUCT_CONTRACTS | `docs/artifacts/02-design/` |
| PRODUCT_TRACEABILITY | `docs/artifacts/02-traceability/` |
| REGRESSION_AND_RELEASE_REPORT | `docs/artifacts/03-test/`, `04-review/`, `07-release/` |

같은 `docs/product/` 아래의 분리 상세도 연결할 수 있다. 다른 원장으로 향하는 링크는 탐색 참조이며 그 원장의 정의를 복제해 검사하지 않는다. 소유 범위 밖 참조는 별도 확인 대상이다. 테스트 정의는 계획으로, 실제 결과는 현재 실행 결과로 구분해야 하며 다른 파일의 상태를 상속하지 않는다. 명시적인 `candidate`/`history` 상태는 현재 정의나 성공 결과를 대신하지 않는다. 결과서의 과거 이력 제목은 기존 호환 기준으로 구분하지만, 요구사항의 "변경 이력 조회" 같은 업무명은 과거 상태로 취급하지 않는다.

절 조회의 12절 출력 제한을 Gate 검사에 재사용하지 않는다. 내용 검사는 연결된 소유 문서를 최대 4단계/128문서/512참조(절당 64참조, 문서당 2MB)까지 읽고, 소유 원본 누락·앵커 오류·경로 위반·예산 초과는 입력 불완전으로 차단한다. 빈 파일이나 링크만 있는 색인으로 필요한 내용을 대신할 수 없다. 의미상 설계 품질/승인까지 자동 판정하는 것은 아니다.

추적/통계는 표의 첫 ID 셀을 실제 항목으로 읽는다. 색인의 ID는 원본 링크로 쓰고 상세 정의를 같은 표에 다시 복사하지 않는다. 같은 정의 행이 반복되면 한 번만 집계하고, 같은 ID의 정의 행 내용이 다르면 출처를 포함한 충돌로 보고한다. 상충된 시나리오나 `Planned` 항목에 코드 경로가 있다는 이유로 구현 완료를 집계하지 않는다. 상세 REQ-ID를 parent REQ로 잘라서 합산하지 않는다. REQ-ID로 시작하는 제목도 하위 절의 본문까지 확인해 요구사항으로 발견하며, 제목 간 의미상 충돌까지 자동 판정하지는 않는다.

회귀 통계는 계획과 실행에 등장하는 같은 REG를 한 번만 세고 현재 결과로 분류한다. SEC-REG는 별도 `tests.security`에 집계한다. 과거 Pass는 현재 Fail/Pending을 해소하지 않는다. `product.document_diagnostics`의 불완전/충돌 표시를 함께 확인한다. 이 통계는 승인 판정이나 테스트 재실행 증명이 아니다.

이 검사 호환은 profile별 필수 목록, Dashboard 탐색 UI, 승인 이력 비교 정책을 변경하지 않는다. 작성 책임/위치와 선택 템플릿은 후속 [Product Document Writing](PRODUCT_DOCUMENT_WRITING.md)을 따른다. 기존 표와 다른 자유 서술 형식의 자동 해석까지 지원한다고 가정하지 않는다. 실제 프로젝트의 이동은 나머지 승인/릴리즈/Dashboard 소비자까지 확인한 뒤 별도 승인으로 진행한다.

## 4. Git과 검증 기록의 경계

별도 Git 증적을 요구하거나 수집하지 않는다. 승인·시험 기록에 commit SHA, `tested_commit`, 소스 fingerprint 또는 Git 스냅샷을 붙이는 절차와 그 일치·신선도로 인수/릴리즈를 차단하는 기준은 폐기한다. 이를 대체하는 필수 원장이나 새 지문 체계도 만들지 않는다.

일반 Git 이력, 브랜치 격리, PR, 커밋, 태그와 릴리즈 노트는 유지한다. 범위·승인·테스트 정의의 revision, 환경 명세 참조, 실제 명령·결과·로그도 유지한다. 이들은 별도 Git 증적이 아니다.

과거 `evidence.commit`이나 소스 관측 JSON은 당시 기록으로 읽을 수 있지만 현재 요구사항으로 되살리거나 의미를 추정하지 않는다. 과거 로그·시험 결과·승인 이력은 재생성하지 않는다.

## 5. 검증 기록 최소판

기존 `execute`에 명시적으로 전달한 검증 명령을 실행하고 증적을 남기는 선택 경로를 추가한다. 문서에 적힌 명령을 무조건 실행하거나 worker/Gate를 자동 진행하지 않는다.

- 호출자는 작업 위치, 명시 명령 argv와 새 증적 경로를 지정한다. `execute --verify`의 schema 2 JSON은 argv, cwd, 실행 시간과 exit code를 기록한다.
- `--source`는 선택적인 설명용 경로다. 파일 내용이나 Git 상태를 수집·비교하지 않으며 검증 범위의 완전성을 증명하지 않는다.
- 원본 소스나 비공개 파일 내용을 증적에 복사하지 않는다. 명령 인자는 그대로 기록하므로 비밀값을 인자로 전달하지 않는다.
- 상세 테스트 로그/HTML과 실제 시험 결과는 기존 테스트 도구와 결과서에 남긴다. JSON은 이 로그나 QA 판단을 대체하지 않는다.
- 기존 증적을 덮어쓰지 않는다. 명령의 exit code가 0이어도 QA/Gate 승인으로 바꾸지 않는다.

Orchestrator는 구현·테스트·의존성·실행 환경의 변경과 시험 범위를 확인해 필요한 관련 재시험을 판단한다. Git 상태나 파일 지문 차이로 자동 재시험을 요구하지 않으며, 커밋을 QA의 선행 조건으로 만들지 않는다. 승인된 필수 검증과 사용자/고객이 요구한 재시험은 유지한다.

1. PR #23의 기존 Product 실행 정책을 main에 반영한다.
2. 이 문서에서 현재 계약/이력과 명령 실행 기록의 경계를 정의한다.
3. 선택형 검증 기록의 명시 명령, 경로, 실행 실패와 과거 기록 읽기 호환성을 확인한다.
4. 절 조회와 current/candidate/history/미분류, 공통 제약, 잘림/경로 경계를 검증한다.
5. 진행 중인 프로젝트의 원본은 변경하지 않고 로컬 복사본으로 기능 하나를 검증한다. 사적 문서/소스는 공개 fixture나 PR에 넣지 않는다. 공개 회귀에는 합성 문서를 사용한다.

문서 바이트/읽기 구간 감소와 실제 모델 토큰/크레딧 절감은 다르다. 비용 개선은 관측한 값만 보고하며 새 문맥 reviewer가 분류 불확실성을 올바르게 보고하는지도 확인한다.

### 6.1 로컬 조회 파일럿 (2026-09-08)

진행 중인 Product 프로젝트 문서의 로컬 복사본으로만 확인했다. 대상 문서 2개의 합계 166,926 bytes에서 12개 구간, 본문 11,952자와 출처/경고 등을 포함한 UTF-8 JSON 30,913 bytes를 반환했다. 모든 반환 구간의 줄 범위와 SHA-256을 원문과 대조했고, 공통 계약/보안/오류 조건 5개도 포함됐다.

이는 완전한 계약 묶음이나 비용 절감 증명이 아니다. 12개 추가 구간이 제한으로 빠졌고 반환 상태는 모두 `unclassified`여서 `incomplete`로 보고됐다. 이 파일럿 당시에는 링크를 자동 추적하지 않았으므로 복사하지 않은 참조와 링크 대상 절을 추가 확인 대상으로 남겼다. 이후 3.1의 조회 보강은 이 과거 관측을 소급해 완전한 계약으로 바꾸지 않는다. 원본 프로젝트, 승인 상태, 기존 문서 내용을 변경하지 않았으며 사적 문서는 공개 fixture에 포함하지 않았다.

부모 대화를 상속하지 않은 reviewer도 구간/해시를 대조하고 미분류 상태에서 현재 적용 계약을 확정할 수 없음을 확인했다. 당시 공개 회귀에는 상태 표식/공통 제약/경로 경계와 Git 검증 대상 식별을 다루는 합성 임시 문서/저장소만 사용했다. Git 식별 검사는 이후 폐기된 요구이며 이 과거 관측을 재작성하지 않는다.

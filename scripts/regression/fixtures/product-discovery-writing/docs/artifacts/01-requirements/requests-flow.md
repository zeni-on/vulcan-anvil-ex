# Rejected Request Flow

문서 작성 연습이며 전체 흐름은 아직 미합의다. 두 사용자 선택만 확인되었고 나머지 정책을 자동 추론하지 않는다.

## Rules And Examples

| 규칙 | 입력 / 행동 | 관측 가능한 기대 결과 | 근거 / 적용 범위 |
| --- | --- | --- | --- |
| 기존 요청 보완·재제출 | '장비 필요' 요청이 반려된 후 설명을 '장비 2대 필요'로 보완해 재제출 | 별도 업무 건을 새로 신청하지 않고 같은 요청에서 최신 내용을 구별할 수 있다. | 대화 연습의 첫 사용자 선택. 권한·상태 코드는 미정. |
| 반려 당시 내용·사유 보존 | 위 요청의 반려 사유가 '수량을 알려주세요'인 상황에서 재제출 | 이전 '장비 필요'와 '수량을 알려주세요'가 남으며 최신 '장비 2대 필요'와 혼동되지 않는다. | 두 번째 사용자 선택. 조회 범위·보존 기간은 미정. |

## Actors And Flow
<!-- vulcan:state=candidate -->

| 순서 / 분기 | 상황 | 행동 / 인계 | 다음 확인 |
| --- | --- | --- | --- |
| 반려 후 보완 | 이전 내용과 사유가 있는 요청 | 요청을 보완할 사람이 내용을 수정하고 재제출한다. | 작성자만 가능한가, 보완 중 내용은 누가 보는가? |
| 재검토 | 보완 제출이 이루어짐 | 검토 대상에 다시 나타나 담당자가 확인한다. | 검토자는 누구이며 어느 시점부터 다시 결정 가능한가? |
| 권한·오래된 화면 예외 | 다른 사람 또는 이전 화면으로 처리 시도 | 거부/허용 조건과 내용 불변 여부를 확인한다. | 기존 권한과 제출 회차 경계를 확인해야 한다. |
